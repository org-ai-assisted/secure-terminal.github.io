The idea in one line

A block-based "terminal chat" (like Warp): the tab bar becomes a left session sidebar, each completed command and its output become a command/reply block, and full-screen programs take over the pane and hand it back. The live prompt is an inline input zone at the bottom -- styled like a composer, but it is the real shell line, so native completion and history keep working.

Try the states

  • Chat -- the default block view with the inline input zone.
  • Tab menu -- how a navigable completion menu could look: an IDE-style dropdown above the input (not an in-document grid).
  • Full-screen TUI -- nano takes the whole pane; the banner shows it returns to chat on exit.
  • Blocks: Rail / Card / Minimal -- three block-styling options to choose from.
  • Toggle Light / Dark as well.

What is faked / deferred

  • No real terminal, shell, or features -- pure HTML/CSS. Sample output is fixed text.
  • The completion-menu driver (native popup vs. a live mini-terminal input zone vs. shell-driven) is an architecture/security question, deferred until the look is chosen.
  • Reliable block boundaries + exit codes would come from a gated OSC-133 handler or a heuristic -- also deferred.
  • The append-only CLI pipeline, sanitizer, and OSC stripping are unchanged in the real plan; blocks are drawn as out-of-document chrome.
  • Identity trust: a trusted cwd/program in the header must come from the kernel (/proc/<pid>/cwd, foreground pgid + /proc/<pid>/comm). OSC 7 is program-asserted and out of trust -- a hostile program can forge it, so it is treated like the quarantined title, not shown as trusted.
