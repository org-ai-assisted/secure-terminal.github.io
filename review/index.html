THE REVIEW BAR

See exactly what a paste carries - before it reaches the shell.

When text crossing the terminal boundary would carry unicode or control characters - a paste coming in, or a selection copied out - secure-terminal holds it and shows a review bar. No byte reaches the shell, or the clipboard, until you choose. It names every hidden character by class, tells you what the text would do, lets you edit it, and shows exactly what each choice would deliver.

When it appears

The bar is not a modal you dismiss on every paste. It appears only when there is something worth a second look.

By default (paste_warn=unicode, copy_warn=unicode) the bar appears when the text carries any non-ASCII or control character - the case a Trojan-Source or pastejacking payload needs. A multi-line paste is held too, even when it is pure ASCII, because a hidden second line could otherwise run the instant you paste. You can set either direction to always (review every paste or copy) or never (sanitize silently, no bar). While the bar is up, input to the child is suspended: nothing crosses until you pick Reject, the ASCII form, or the unicode form.

The hidden-character breakdown

A one-line summary tells you the headline; a table names every class present, counts it, and shows what is not present too - so "nothing else is hiding" is explicit, not assumed. Each class is tinted by the same risk colour the terminal draws it in.

ClassWhat it isExample
↔Bidirectional controlreorders the visible text (Trojan-Source)
␀Control characterC0 / DEL / C1 bytes
␣Invisible / zero-widthjoins or hides characters you cannot see
≈Look-alike (homoglyph)a Cyrillic letter posing as its ASCII twin
◌Combining (Zalgo)stacked accents piled on a base letter
┼Box-drawing / blockshonest line-drawing glyphs, low risk
ÀOther non-ASCIIordinary foreign or accented text

The summary folds these into a short sentence ("hides 1 bidirectional control, 1 invisible character"); the table is the full, copyable detail. Alongside sits a mirror pane that renders exactly what each choice would deliver - so a look-alike command is de-obfuscated to its real ASCII before you send it, and cannot hide behind a button label.

Structure, and never-auto-run

Beyond the characters, the bar summarises the shape of the paste - and guarantees it cannot run on its own.

  • Lines - how many commands it would be; a multi-line paste is flagged, because each line is a command.
  • ✓ Runs on its own? No. A paste never auto-executes: at a shell prompt the trailing submit is removed, so the command waits at the prompt for your own Enter. Under a full-screen program that has asked for bracketed paste, the program receives the text as inert data instead.
  • Length - characters and bytes (marked as a scanned prefix when a very large paste is only partly scanned, so a capped count is never shown as a definite total).

Editable before delivery

If the paste is almost right, you do not have to reject it and start over.

The held text is editable in the bar. Trim the risky part, and the summary, the breakdown and the mirror all update from what you typed. Delivery then sends exactly your edited buffer - still run through the same sanitizer on the way out, so an edit can never bypass the neutralization. What the bar shows is what crosses.

Paste and copy are not symmetric - by design

You may notice a copy raise the bar while pasting the same text back does not. That is correct, not a bug.

A paste is inspected as the raw clipboard bytes, in every display mode. A Ctrl+C copy is inspected as the on-screen selection. In the box, reveal and detail display modes the selection is already sanitized to ASCII, so nothing risky can reach the clipboard and no review is needed; only in show mode, where real glyphs are kept, does a copy raise the bar. A mouse selection (the X11 primary buffer) and drag-and-drop are always hard-stripped to ASCII, so a middle-click paste of a selection is safe without a review.

So when a copy raises the bar but pasting the same text back does not, it is because what reached the clipboard was already safe - the terminal reviewed the risky direction and left the harmless one alone.
